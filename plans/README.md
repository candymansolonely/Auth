# plans/

Implementation plans live here, one Markdown file per feature/ticket, e.g. `2026-09-19-user-authentication.md`.

Suggested shape for each plan file:

- **Goal** — what the feature/change needs to accomplish and why.
- **Scope** — what's in vs. explicitly out.
- **Design** — which layer(s) touched (`Domain` / `Application` / `Infrastructure` / `WebAPI`), key types/interfaces to add.
- **Steps** — ordered checklist of the work.
- **Open questions** — anything blocking that needs a decision before/while implementing.

Keep completed plans in place (don't delete) — they double as a changelog of *why* a feature was built, which git history alone doesn't capture.
